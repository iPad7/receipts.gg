# receipts.gg — Claude Code 인수인계 가이드

**기준일:** 2026-10-13  
**문서 패키지:** handoff v0.3  
**진행 상태:** 기획·논리 설계 초안 작성 / 실제 코드 구현은 아직 시작하지 않았다고 가정(사용자의 로컬 개발 상태는 별도 확인 필요)

## 1. 인수인계 전에 알아야 할 것

- 제품 가제: **receipts.gg**. 실제 도메인 소유·DNS·운영 사실은 확인되지 않았다.
- 목적: SOOP 소규모 개인 버튜버를 위한 **맞춤형 공개 홈페이지 + CMS + RMS(룰렛 보상 이행 관리)**.
- 1차 목적은 **백엔드·응용 AI 엔지니어 취업 포트폴리오**이며 실제 스트리머 파일럿은 도전 목표다.
- 운영자 실사용 인터뷰는 확보되지 않았다. 공개 사례에 기반한 가설과 검증된 기술 요구를 구분한다.
- 기술 기준: FastAPI/Python, PostgreSQL, SQLAlchemy, Alembic, uv, Next.js/TypeScript, Modular Monolith.
- **개발 순서 확정:** 백엔드 구현·검증 완료 → 프론트엔드 구현. API 문서나 HTTP 클라이언트로는 그전에도 백엔드 검증 가능.
- RMS에서는 `RewardAcquisitionEvent → RewardGrant → Fulfillment(필요한 경우)` 관계를 유지하고 데이터 정합성·감사 로그가 필수다.
- 범위 밖: 자체 룰렛 실행, SOOP 채팅 자동 수집, 제재 자동화, 시청자 로그인, 자동 위플랩 연동, 셀프 온보딩.

## 2. 문서 읽는 순서

1. `CLAUDE.md` — 최우선 **협업 절차 및 편집 승인 방식**.
2. `README.md` — 프로젝트와 문서 지도.
3. `DEVELOPMENT_PLAN.md` — 현재 BE-00, 단계·게이트·완료 기준.
4. `SOFTWARE_ARCHITECTURE.md` 및 `docs/adr/` — 기술 선택 및 제약.
5. 작업별 선택: `PRD.md`, `DOMAIN_MODEL.md`, `AGGREGATE_DESIGN.md`, `IA_USER_FLOW.md`, `WIREFRAMES.md`.

읽기 순서는 중요도 서열이 아니라 **인수인계를 효율적으로 진행하기 위한 경로**입니다. 문서가 충돌하면 임의로 선택하지 말고 보고합니다.

```text

개발은 Backend First로 진행하며, 현재 목표는 BE-00(개발 환경 및 저장소 초기화)입니다.

이번 응답에서는 기존 저장소와 환경을 읽기 전용으로 점검한 뒤,
다음 내용만 사전 보고해주세요.
1. 현재 저장소/환경에서 확인한 사실과 확인하지 못한 사항
2. 제안하는 Monorepo 디렉터리 구조와 근거
3. BE-00의 세부 실행 계획 및 생성·변경 예정 파일
4. 제가 판단해야 할 기술 선택 사항과 추천안
5. 검증 명령 및 BE-00 완료 기준
6. 해당 내용을 이해하는 데 필요한 핵심 학습 포인트

반드시 사전 보고 → 의사결정 검토 → 저의 명시적 승인 → 구현·검증 → 사후 보고
사이클을 따라주세요. 승인 전에는 파일 생성·수정·삭제, 패키지 설치,
실행 환경 변경, Git 커밋 및 배포를 하지 마세요.

코드 편집 승인을 요청하는 경우 파일별 수정 목적·내용·이유·학습 포인트를
2~5문장으로 미리 설명해주세요. 아직 구현을 시작하지 마세요.
```

## 4. 로컬에 파일을 적용할 때

- 이 ZIP에 포함된 문서들은 사용자 로컬 폴더를 자동으로 수정하지 않는다.
- 이전 로컬 파일에 사용자가 별도 편집한 내용이 있다면 **비교 후 병합**한다.
- 기존 `docs/adr/`가 있으면 파일명 충돌과 변경된 참조 절 번호를 확인한다.
- `CLAUDE.md`와 `DEVELOPMENT_PLAN.md`를 반드시 저장소 루트에 둔다.
- 첫 작업의 승인 전에는 Claude가 계획만 세워야 한다.

## 5. 변경 시 유의 사항

- 현재 개정된 문서들도 실제 코드 구현과 실사용 검증 전의 설계 기준선이다.
- 문서에 없는 요구사항을 구현할 경우 PRD/SA/ADR 중 영향받는 문서의 변경안도 함께 보고한다.
- 실제 파일 내용과 본 문서의 가정이 다르면, **실제 저장소**를 확인한 후 그 차이를 먼저 보고한다.
