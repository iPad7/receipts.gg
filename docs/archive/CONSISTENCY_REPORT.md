# receipts.gg (가제) — 문서 정합성 감사 보고서

- **점검일:** 2026-10-13
- **결과물 버전:** v0.2
- **확인 범위:** 제공 패키지의 문서 6개 + ADR 6개

## 1. 작업 범위와 정확한 한계

사용자가 로컬 폴더에 복사해 둔 실제 Markdown 파일은 이 환경에서 접근되지 않았습니다. 따라서 **로컬 파일을 수정했다고 주장하지 않습니다**. 대신 대화에서 공동 작성했던 문서를 기준으로 일관된 개정판을 재구성했습니다. 로컬에서 사용자가 독자적으로 수정한 사항은 반영되지 않았을 수 있습니다.

기존 파일 일부(ADR 6개)는 작업 환경에서 실제 파일을 확인하여 개정했고, PRD·도메인·IA·와이어프레임·SA 본문은 앞선 대화의 초안을 바탕으로 새 Markdown 수정본으로 만들었습니다.

## 4. 영향도가 큰 기존 오류의 해설

### 4.1 이행 불필요 보상

예: `RewardGrant.ACTIVE`이지만 즉시 지급되어 `Fulfillment`가 생성되지 않는 보상은 유효 권리이면서도 미이행·이행 완료 어느 쪽에도 포함되지 않습니다. 따라서 집계는 다음과 같습니다.

`유효 보상 = (이행 대기 + 이행 중) + 이행 완료 + 이행 불필요`

### 4.2 단순 CANCELLED UI 제거

정당한 보상 이행 지연은 보상 권리를 삭제할 근거가 아닙니다. 취소라는 UI만 두면 미이행 기록을 쉽게 없앨 수 있으므로 `오기록 무효화`와 `완료 정정`을 구분했습니다.

### 4.3 공개 닉네임 조회는 인증이 아님

운영자가 공개 허용한 보상은 조회할 수 있지만, 닉네임을 입력한 사람이 실제 소유자인지 확인할 수는 없습니다. PUBLIC 수정·수령·주소 조회 기능을 MVP에서 제공하지 않습니다.

## 5. 아직 미결정인 사항

1. 실사용·운영자 인터뷰 없이 제품 문제 가설이 검증되지 않았습니다.
2. `receipts.gg`의 도메인 보유·등록·상표 충돌 가능성을 확인하지 않았습니다.
3. PostgreSQL 물리 테이블·인덱스·복합 외래키 구조는 아직 설계하지 않았습니다.
4. CMS 공지의 상세 데이터 모델과 이미지 처리 정책은 별도 설계가 필요합니다.
5. 개인정보 보존·삭제와 감사 로그 사이의 법적·운영적 정책이 필요합니다.
6. 외부 SOOP/위플랩 API 제공 범위는 구현 전 최신 공식 문서로 재검증해야 합니다.

## 6. 로컬 문서에 적용할 때

**이 패키지는 수정된 새 파일 묶음이며, 사용자의 실제 로컬 폴더를 원격 수정한 것이 아닙니다.**

1. 로컬 6개 문서를 백업합니다.
2. VS Code에서 같은 이름의 파일끼리 Compare로 확인합니다.
3. 사용자가 별도로 고친 내용은 병합합니다.
4. 수정본으로 대체한 뒤 이전 용어/취소 정책/집계 오류가 남지 않았는지 전체 검색합니다.
5. `docs/DOC_SYNC_CHECKLIST.md`를 통해 잔여 항목을 추적합니다.
