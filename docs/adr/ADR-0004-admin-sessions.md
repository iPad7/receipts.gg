# receipts.gg (가제) — ADR-0004 — 비로그인 Public / 관리자 서버 세션

- 개정: 2026-10-13 / 문서 패키지 v0.3 (참조 절 보정)
- 날짜: 2026-10-13
- 상태: Proposed
- 참조: PRD.md FR-007, SOFTWARE_ARCHITECTURE.md §8

## 맥락
시청자에게 회원가입을 요구하지 않는 것이 핵심 경험이다. 반면 관리자 변경 작업 및 비공개 보상 정보는 안전하게 보호해야 한다.

## 결정
Public은 인증 없이 읽기 전용으로 운영하고, 관리자는 배포·관리 절차로 생성한 계정으로 로그인한다. 서버 측 세션을 Secure/HttpOnly/SameSite 쿠키로 전달한다. 세션 무효화, 세션 기반 CSRF 토큰 검증, Origin 검사, 로그인 속도 제한, 서버 측 사이트 권한 검증을 적용한다. 공개 API는 관리자 응답 스키마를 재활용하지 않는다. 개별 RewardGrant의 공개 여부는 기본 비공개다. 닉네임 검색은 시청자 본인 인증을 의미하지 않는다.

## 검토한 대안
- 시청자 OAuth/로그인: 시청자 본인 확인에는 유용하나 P0 범위와 검증 부담이 커진다.
- 브라우저 localStorage의 장기 JWT: 토큰 노출·폐기 정책을 추가로 관리해야 한다.
- UI 메뉴 숨기기만 하는 권한 통제: API 직접 호출에 취약하다.

## 결과와 트레이드오프
서버가 세션 저장 및 만료를 책임진다. Auth 코드를 직접 구현할 때 높은 테스트 요구가 발생하므로 검증된 라이브러리와 안전한 표준 패턴을 우선 사용한다.

## 재검토 조건
다중 관리자, 매니저 역할, 시청자 본인 확인이 실제 요구가 되면 권한 모델과 OAuth 도입 여부를 재검토한다.
