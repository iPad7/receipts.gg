# receipts.gg (가제) — ADR-0001 — Modular Monolith 채택

- 개정: 2026-10-13 / 문서 패키지 v0.3 (참조 절 보정)
- 날짜: 2026-10-13
- 상태: Proposed
- 참조: SOFTWARE_ARCHITECTURE.md §2·§4·§6, AGGREGATE_DESIGN.md

## 맥락
1인 개발이며, MVP에는 CMS·RMS·인증·감사 로그가 포함된다. 보상 발생 사건과 여러 보상 권리를 하나의 원자적 트랜잭션으로 생성해야 한다.

## 결정
FastAPI 애플리케이션 한 개와 PostgreSQL 한 개를 운영하되, 모듈의 공개 인터페이스와 소유권을 분리한다. 내부 모듈 간 호출은 프로세스 내 Application Service를 사용한다.

## 검토한 대안
- MSA: 서비스별 배포와 독립 확장은 가능하지만, 분산 트랜잭션·네트워크·운영 부담이 MVP에 과도하다.
- 단순 계층형 모놀리스: 시작은 쉽지만 업무 도메인 사이의 무분별한 직접 의존이 발생하기 쉽다.

## 결과와 트레이드오프
한 번에 배포하며, 모듈 간 독립적인 배포는 불가능하다. 대신 트랜잭션과 디버깅을 단순화하고, 모듈 경계 테스트로 결합도를 관리한다.

## 재검토 조건
서로 다른 모듈의 확장·배포 주기 또는 장애 격리 요구가 실제로 발생하면 재검토한다.
