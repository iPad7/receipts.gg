# receipts.gg (가제) — ADR-0002 — Next.js + FastAPI 분리 구성

- 개정: 2026-10-13 / 문서 패키지 v0.3 (참조 절 보정)
- 날짜: 2026-10-13
- 상태: Proposed
- 참조: SOFTWARE_ARCHITECTURE.md §2·§7·§9·§10

## 맥락
공개 홈페이지는 모바일·SEO·브랜딩이 중요하고, 관리자 콘솔은 복잡한 폼·데이터 그리드가 필요하다. 백엔드 기술 역량은 Python 도메인 로직으로 보여주고자 한다.

## 결정
Next.js App Router/TypeScript로 웹 UI를, FastAPI/Python으로 REST API를 구현한다. 브라우저 접근은 가제 도메인 소유와 무관하게 배포 시 설정된 동일한 HTTPS 오리진 아래 웹페이지와 `/api/v1`로 분기한다. 백엔드를 유일한 업무 규칙의 실행 위치로 삼는다.

## 검토한 대안
- Next.js만 사용: 배포가 단순하지만 Python 백엔드와 독립적인 도메인 계층이라는 포트폴리오 목적을 충족하기 어렵다.
- FastAPI 템플릿 기반 풀스택: 구성은 단순하지만 맞춤형 홈페이지·복잡한 Admin UI의 개발 경험을 충분히 드러내기 어렵다.

## 결과와 트레이드오프
프론트·백엔드 간 계약 관리와 두 런타임의 배포가 필요하다. OpenAPI를 계약의 원천으로 삼고 타입 생성을 자동화하는 방안을 우선 검토한다. Next.js 서버 렌더링과 API 응답 캐시는 데이터별로 명시적으로 제어한다.

## 재검토 조건
프론트·백엔드 분리 비용이 기능 규모에 비해 과도해지거나 배포 제약이 커지면 재검토한다.
