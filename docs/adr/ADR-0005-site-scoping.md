# receipts.gg (가제) — ADR-0005 — 단일 고객 배포에서 사이트 범위를 명시

- 개정: 2026-10-13 / 문서 패키지 v0.3 (참조 절 보정)
- 날짜: 2026-10-13
- 상태: Proposed
- 참조: SOFTWARE_ARCHITECTURE.md §4·§6·§8

## 맥락
`receipts.gg`는 제품 가제이며 고객별 `StreamerSite` 및 `site_slug`와 별개다. 첫 고객에게 맞춤 홈페이지를 제공하되, 고객이 늘어날 때 같은 기능을 복사·재구현하는 상황은 피하고자 한다.

## 결정
MVP는 사이트 하나를 운영하지만 StreamerSite를 최상위 소유 범위로 둔다. 사이트별 운영 데이터와 관리자 권한 확인에 `site_id`를 사용한다. API에서 전달된 임의의 site_id를 그대로 신뢰하지 않고 인증된 관리자의 허용 사이트와 대조한다. Public에서도 요청 URL의 사이트 문맥을 서버가 확정한다. MVP의 `/` 경로는 단일 사이트이고, 고객별 커스텀 도메인 지원은 후속 과제다. `receipts.gg` 도메인의 실제 등록·소유는 확인되지 않았다.

## 검토한 대안
- 모든 데이터를 단일 전역 레코드로 가정: 초기 구현은 단순하지만 나중에 사이트 분리·이관이 어렵다.
- 출시 전에 완전한 멀티테넌트 SaaS 구축: 온보딩·과금·테넌트 관리 비용이 과도하다.

## 결과와 트레이드오프
키와 소유권 검증이 일부 추가되지만 코드 재사용성과 격리 테스트에 유리하다. 이것만으로 멀티테넌트 보안이 완성되는 것은 아니며, 필요시 DB 수준 제약과 RLS 등을 추가 검토한다.

## 재검토 조건
서로 다른 고객을 하나의 운영 DB에서 동시에 호스팅할 때 테넌트 격리 정책을 전면 재검토한다.
