# receipts.gg (가제) — Low-fidelity 와이어프레임 설계서

- **버전:** 0.2
- **개정일:** 2026-10-13
- **상태:** 화면 설계 기준선 (최종 UI 디자인 아님)
- **참조:** `PRD.md`, `IA_USER_FLOW.md`, `DOMAIN_MODEL.md`

## 1. 범위와 원칙

`receipts.gg`는 서비스 가제이다. 버튜버 사이트의 도메인·캐릭터·테마는 고객별 설정값이다. PUBLIC은 모바일 우선의 브랜드 홈페이지, ADMIN은 데스크톱 우선의 작업 콘솔로 설계한다. 색상·폰트·아트워크는 아직 정하지 않는다.

- 상태 변경의 최종 검증·저장은 백엔드 책임이다.
- 공개 보상은 기본 비공개이며, 닉네임 검색만으로 시청자 소유권을 확인하지 않는다.
- 보상 무효화는 일반 완료/진행 상태 버튼과 분리한다.

## 3. Public 화면

### WF-P01 — Desktop Home

```text
+-------------------------------------------------------------------+
| [로고/스트리머명]    HOME  ROULETTE  REWARDS        [SOOP ↗]          |
+-------------------------------------------------------------------+
| [프로필: 이름, 소개, SNS]         [캐릭터 대표 이미지]                |
| [방송국 방문 CTA]                                                 |
+-------------------------------------------------------------------+
| [이번 주 일정]                    [최근 게시 공지]                   |
+-------------------------------------------------------------------+
| [룰렛 확률표 →]                   [공개 업보 조회 →]                |
+-------------------------------------------------------------------+
| Footer                                                            |
+-------------------------------------------------------------------+
```

- 브랜딩 및 스트리머 소개를 최상단에 배치한다.
- 비게시 공지·숨김 콘텐츠는 존재를 노출하지 않는다.
- SOOP 방송국은 외부 링크로 이동한다.

### WF-P02 — Mobile Home

```text
+--------------------------+
| [스트리머명]        [☰]   |
| [캐릭터 대표 이미지]      |
| [이름 및 소개]           |
| [SOOP 방송국 ↗]         |
| [SNS 링크]              |
| [방송 일정]             |
| [최근 공지]             |
| [룰렛 →] [업보 →]       |
+--------------------------+
```

- Hero를 세로 배치하고 CTA 터치 영역을 충분히 확보한다.
- 이미지가 로딩되지 않아도 주요 링크와 일정은 사용 가능해야 한다.

### WF-P03 — Roulette

- 공개 룰렛 선택 → 이름·설명·보상 목록·수동 입력 확률·마지막 수정 시각.
- 확률 미입력 시 `정보 없음`으로 표시하며 추정 숫자를 만들지 않는다.
- 룰렛을 직접 돌리는 버튼·결제 기능은 제공하지 않는다.
- 비공개 룰렛은 목록과 직접 접근 모두 차단한다.

### WF-P04 — Rewards

**데스크톱:** 상단 검색·보상/상태 필터 → 결과 표 → 선택 상세.
**모바일:** 검색 → 접히는 필터 → 개별 보상 카드 → 상세.

```text
[공개 업보 조회] [갱신 시각]
[닉네임 검색] [보상 필터] [상태 필터]
------------------------------------
공개 표시명 | 보상 | 상태 | 획득 시점
------------------------------------
[공개된 상세 / 이행 상태]
```

- 공개 조건을 만족하는 Grant만 반환한다.
- `대기`, `이행 중`, `완료`, `이행 불필요`의 의미를 분리한다.
- 비공개 보상 수량·비공개 메모·계정 ID는 API에도 내보내지 않는다.
- 익명·공개 닉네임 표시 방식을 추후 사이트 정책으로 조정한다.

### WF-P05 — Notice Detail

- 제목, 게시 시각, 본문, 공개 링크, 홈으로 돌아가기.
- 임시저장/비게시 공지에 직접 URL로 접근해도 공개되지 않는다.

## 4. Admin 화면

### WF-A01 — Login

- 중앙 로그인 카드, 계정 입력, 비밀번호, 오류 안내.
- 성공 후 대시보드로 이동하고 로그인·권한 오류를 구분한다.
- 서버 세션 사용; 세션 토큰은 화면 또는 저장소에 표시하지 않는다.

### WF-A02 — Dashboard

```text
+-------------------------------------------------------------------+
| [사이드바] | [사이트명] Dashboard         [+ 새 업보 등록]           |
|  홈       | [유효 보상] [미이행] [완료] [이행 불필요]               |
|  CMS      | [진행 중 업보] [최근 등록 기록]                         |
|  룰렛     | [미이행 목록: 시청자/보상/상태/상세]                    |
|  업보     |                                                      |
|  감사     |                                                      |
+-------------------------------------------------------------------+
```

- **전체 유효 보상** = ACTIVE Grant.
- **미이행** = PENDING + IN_PROGRESS Fulfillment.
- **완료** = FULFILLED Fulfillment.
- **이행 불필요** = Fulfillment가 없는 ACTIVE Grant.
- 전체 유효 보상 = 미이행 + 완료 + 이행 불필요(이행 중은 미이행의 부분집합).
- VOIDED 보상은 유효 집계에서 제외한다.

### WF-A03 — CMS

영역: 프로필/대표 이미지/링크/방송 일정/공지.
- 프로필·링크·일정: 저장 후 공개 적용.
- 공지: 초안 저장·게시·게시 취소 구분.
- 이미지 업로드: 허용 형식·크기·저장 결과 검증.
- 페이지 블록 드래그·앤·드롭 빌더는 MVP 제외.

### WF-A04 — Roulette Management

- 룰렛 목록: 이름·보상 수·공개 여부·최근 변경.
- 편집기: 이름, 설명, 확률(선택), 보상 추가·비활성화, 공개 설정.
- 비활성화는 과거 Grant 스냅샷을 변경하지 않는다.

### WF-A05 — Reward Registration

```text
+--------------------------------------------------+
| 새 업보 등록                                     |
| 사건 유형 [ROULETTE_DRAW/MANUAL_AWARD]           |
| 시청자 [선택 / 신규 등록]                        |
| 룰렛   [선택 가능]                               |
| 보상    [종류] [수량] [+보상 추가]               |
| 발생 시각 [알려진 경우]                          |
| 공개 [기본 OFF] / 내부 메모                      |
| ------------------- [요약] --------------------- |
| 생성할 Grant N개 / 이행 작업 M개                |
| [취소]                        [등록]             |
+--------------------------------------------------+
```

- `LEGACY_IMPORT`는 모델 용어이며 별도 CSV 이관 UI는 P1이므로 MVP 일반 등록 화면에 강제 노출하지 않는다.
- 닉네임이 겹치면 자동 병합하지 말고 관리자에게 참조 구분을 요청한다.
- 한 사건에서 복수 항목을 추가하고 제출 전 합계를 확인한다.
- 등록 요청에 멱등성 키를 사용하고 중복 클릭·네트워크 재시도 시 안전하게 처리한다.

### WF-A06 — Reward Management / Detail

**목록:** 시청자·보상·획득·이행 상태·공개 여부·작업. 검색/필터(보상, 룰렛, 상태, 날짜).

**상세:** 사건 근거, 당시 보상 스냅샷, 권리 상태, 이행 상태, 요청 옵션, 비공개 메모, 변경 이력.

**액션 분리**
- `이행 시작` (`PENDING → IN_PROGRESS`)
- `이행 완료` (`PENDING/IN_PROGRESS → FULFILLED`)
- `완료 기록 정정` (`FULFILLED → IN_PROGRESS`, 사유 필수)
- `오기록 무효화` (미완료 ACTIVE Grant만, 사유 및 별도 확인 필수)

**금지:** 유효한 보상을 단순 CANCELLED로 만드는 독립 버튼. 이미 완료된 Grant 즉시 무효화.

**모바일:** 표를 카드 목록으로 전환하고 진행/완료 버튼을 제공하며, 무효화는 확인 절차에서 실행한다.

### WF-A07 — Audit Log

- 시간·작업자·변경 유형·대상·전후 상태·사유.
- 관리자 읽기 전용. PUBLIC에는 노출하지 않는다.
- 변경 기록을 삭제하는 일반 UI를 두지 않는다.

## 5. 공통 UI 상태·접근성

| 상태 | 정책 |
|---|---|
| Loading | 중복 작업 방지, 실제 커밋 전 성공 표시 금지 |
| Empty | 정상적으로 데이터가 없음 안내 |
| Error | 원인·재시도 가능 여부 제공 |
| Unauthorized | 로그인 안내 |
| Forbidden | 접근 권한 부족 안내 |
| Conflict | 중복 키 불일치/오래된 버전의 충돌 안내 |
| Success | 서버 성공 후 목록·집계 갱신 |

- 버튼·상태를 색상만으로 구분하지 않는다.
- 탭·키보드 탐색, 작은 화면의 터치 영역, 이미지 대체 텍스트를 고려한다.
- 입력 실패 시 폼 내용을 보존한다.
